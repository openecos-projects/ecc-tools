# iPW SDC Syntax Compatibility

iPW accepts `all_delay_corners` in its internal SDC interpreter so that the
default constraints generated by [ECC #354](https://github.com/openecos-projects/ecc/pull/354)
can be read through to the end. Tcl evaluates nested queries before executing
the enclosing command, even when iPW ignores that enclosing timing constraint:

```tcl
set_timing_derate -early 0.95 -clock -delay_corner [all_delay_corners]
```

## Compatibility Boundary

- `all_delay_corners` accepts no arguments, emits a syntax-only warning, and
  returns an empty Tcl collection. It does not create or select analysis corners.
- Existing `set_timing_derate`, `set_max_transition`, `set_max_capacitance`,
  `set_units`, and other ignored timing commands retain their previous iPW
  behavior. This change does not validate or implement their missing semantics.
- No OCV derates, electrical-limit checks, unit conversion, or power-calculation
  changes are introduced. Real corner/constraint support requires follow-up work.
- Existing power-relevant clock, transition, load, and case-analysis handling is
  unchanged. Unknown commands and invalid arguments to the new query still fail;
  there is no generic unknown-command suppression.

The `ipw_sdc_compatibility` CTest covers the generated SDC command sequence with
physical and virtual clocks, the empty query result, preserved clock/slew/load
values, and error handling. Passing this parser regression does not establish
complete SDC semantics or end-to-end ECC harden success.
