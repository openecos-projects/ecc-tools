# PinAccessor 维护说明

## 1. 模块边界与阅读入口

PA 从 Database 读取 pin 几何、障碍、层轨道和 via 规则，为 pin 选择 AP，
生成从 AP 到 target 的接入线段及 minimum-area patch，并输出最终违例。
它不负责整条 net 的详细布线，也不以候选区域的几何裁剪代替完整 DRC。

| 维护主题 | 主要入口 | 主要数据 |
| --- | --- | --- |
| 候选 AP、目标坐标 | initAccessPointList、getLegalShapeList、getAccessPointList、buildPinTargetCoordList | PAPin、PALegalShape、AccessPoint |
| 迭代、分块与归属 | routePAModel、buildPinOwner、buildBoxSchedule、splitPAResult | PAModel、PABoxId |
| 环境与任务导入 | buildPAEnvironment、initPATaskList、initPATaskResult | PABox、PATask、PATaskResult |
| 图搜索、via 与 AP 选择 | routePATask、expandSearching、selectAccessPoint、getRoutingSegmentList | PARouteState、PANode |
| Patch 生成与选择 | patchPATask、getCandidatePatchList、selectPatch、isPatchImprovement | PAPatchState、PAPatch、PAPatchSelection |
| DRC 范围与输入 | buildPatchDETask、getRouteViolationList、getDirtyRouteViolationList、getFullRouteViolationList | DETask、PAFixedGeometry |
| 结果快照、发布与清理 | updateBestResult、selectBestResult、uploadPABoxResult、updatePAModel、freePABox | PABoxResult、PAModel |

## 2. 整体运行流程

```text
access
  initPAModel -> setPAComParam
  initAccessPointList(false) -> buildAccessPointRTree
  routePAModel
    对每组 PAIterParam：
      setPAIterParam
      initPABoxMap -> buildPinOwner -> 清除 model 的 initial_routing
      buildBoxSchedule -> splitPAResult -> routePABoxMap
      updateViolation -> updatePAModel -> freePABoxMap
      updateBestResult -> summary / CSV
    违例清零可提前结束
    首轮结束但还需下一轮时：刷新带 via 候选的 AP，再重建 AP RTree
    selectBestResult(model)
  uploadAccessPoint -> uploadAccessResult -> uploadAccessPatch -> uploadViolation
```

每次迭代重新划分 box，改变 offset 后重新确定 pin owner。

### Stage 与并行边界

`routePABoxMap` 负责批次调度和进度统计，`routePABoxList` 负责单个 stage 的完整处理流程：

```text
buildPAEnvironment(..., false)
  -> buildRouteViolation
  -> parallel：buildAccessPoint + initPATaskList + initPATaskResult
  -> barrier
  -> parallel：routePABox(model, box)，违例移入各自的 PABox.route_violation_list，释放工作区
  -> barrier
updateRouteViolation(model, box_id_list)：按 box ID 汇总去重，释放 box 违例列表 -> 下一 stage
```

Stage 按间隔挑选 active box。环境构建可并行扫描 owner，但写入同一目标 box 时加锁。
求解阶段每个 worker 只修改自己的 box、task 和本 box 所拥有 pin 的 AP。
本 stage 的 active owner 不作为其他 active box 的环境来源。

### Box 与 Task

`routePABox(model, box)` 管生命周期，`routePABox(box)` 管重跑循环。
前者按需构建 fixed geometry、track axis、node graph、shadow 和环境投影，
后者按 task schedule 执行下列顺序：

```text
removeTaskResult
  -> routePATask -> patchPATask -> addRoutedTimes
完成本轮任务后：
updateRouteViolationList -> updateAccessPoint -> updateBestResult -> updateTaskSchedule
重跑循环结束后：
实际执行过布线轮次 -> selectBestResult(box)，仅恢复最佳快照到 curr_result
统一返回生命周期流程：
uploadPABoxResult -> freePABox
```

`selectBestResult(box)` 只恢复最佳快照；`uploadPABoxResult` 将当前线段、patch 移回 owner 表、AP 写回 pin，并移出待汇总违例。

## 3. 数据与所有权

| 数据 | 含义与生命周期 |
| --- | --- |
| PAModel | 本次 PA 的 net/pin、候选 AP 索引、迭代参数、跨迭代结果与最优快照 |
| PAPin.access_point_list | 候选集合；AP RTree 和 box 借用其元素地址，迭代求解期间不得扩容、排序或重建 |
| PAPin.access_point | 当前选中的 AP；与候选集合是不同对象，不能把候选集刷新当成结果发布 |
| PABox.net_pin_own_* | box 持有的线段与 patch 向量；跨 stage 保留，按 pin 唯一归属 |
| PABox.net_pin_env_* | 邻居结果及本地未创建 task 的 owner 结果的借用指针；求解期间只读 |
| PATask | 稳定 task_idx、net/pin 身份、两组坐标、调度属性、当前选中 AP 指针 |
| PABox.curr_result | 按 task_idx 索引的当前 AP/线段/patch，以及 box 违例 |
| PABox.route_violation_list | box 求解结束后待汇总的违例；并行期间各 box 独立持有，stage barrier 后归并到 model 并释放 |
| PABox.best_result | 与当前结果分离的完整快照；valid 标记区分未保存与合法空结果 |
| PARouteState / PAPatchState | 单任务搜索或补丁的工作区，不是最终结果所有者 |

线段与 patch 的主数据流相同：

```text
PAModel result maps
  -- splitPAResult / move --> PABox owner maps
  -- initPATaskResult / move tasked pins --> curr_result[task_idx]
  -- 实际布线时 updateBestResult / copy --> best_result
  -- selectBestResult / move --> curr_result
  -- uploadPABoxResult / move --> PABox owner maps
  -- updatePAModel / move --> PAModel result maps
```

无需布线时，从导入后的 curr_result 直接进入 uploadPABoxResult，不经过 best_result。

`initPATaskList` 只定义任务，`initPATaskResult` 才移动 owner 结果。
没有创建 task 的本地结果仍留在 owner 表，并作为 env 提供给求解器。
因此扫描 env 和 live task 已经覆盖求解环境，不能再把 owner 全表重复加入代价或 DRC。
env 的容器去重基于指针身份，不应擅自合并不同来源的重合几何。

## 4. 候选几何与目标坐标

候选准备分为层选择、收缩与障碍裁剪、AP 枚举与选择、target 生成四步。

- Core pin 按层号降序尝试；非 core pin 优先奇数层，同类再按层号降序。
- 收缩尺寸取 wire 半宽与 via enclosure 半尺寸的较大值。
- 障碍查询按指定层顺序执行；两次查询都使用原始收缩窗口，不用中途裁剪后的窗口。
- 裁剪若得到空集合，保留上一份非空候选并停止继续裁剪。
- 默认 AP 模式允许退回原始 pin shape；指定 via 模式本身不做这个退回。
- Via 模式生成不到 AP 时，initAccessPointList 再尝试默认模式；最终仍为空则报错。

`buildPinTargetCoordList` 按 source layer 收集 AP 窗口，
`buildLayerTargetCoordList` 先按 x 合并 y 区间，再枚举 source layer 的 track 坐标，
将坐标放到 `getTargetLayerIdx` 确定的目标层。
后者向结果列表追加，不负责清空；不同 source layer 还可能映射到同一 target layer，
所以外层保留跨层去重。最终复制到 pin 的紧凑向量，避免永久持有中间容器的过大容量。

## 5. 单任务路由契约

每个生产 task 恰有两个非空 PAGroup：front 是 source AP，back 是 target。
`initSingleRouteTask` 在修改工作区前检查数量、角色和非空条件。
多个 source/target 坐标表示可选端点，不表示必须逐一连接所有坐标。

```text
initSingleRouteTask
  -> routeSinglePath：多源搜索，到达任意 target 即成功
  -> getRoutingSegmentListByNode：提取带 via 身份的父链
  -> selectAccessPoint：回溯父链起点，选定原始 AP 对象
  -> resetSinglePath：清理队列与节点搜索状态
  -> updateTaskResult：树重建、恢复 via 身份、发布线段并投影环境
  -> resetSingleRouteTask
```

PARouteState 只保存扁平 source/target 列表、source-node/AP 映射、当前任务、
临时线段、open queue、当前 path head 和一份 visited 列表。

不可达由 routeSinglePath 返回 false，routePATask 报出 box/net/pin/task 后停止；
不能伪装成空路径成功。起点与终点重合则是合法成功，线段集合可以为空。
不能在 AP 回溯和线段提取前清理 parent 指针。

Via 选择保留默认 master、AP 候选限制和随重跑次数轮换的 tie 策略。
树重建会丢失 via master 标识，因此 getRoutingSegmentList 显式保存、恢复并检查这些标识。

## 6. Patch 生成与接受策略

`searchViolation` 选择当前 task net 的 box 内 minimum-area 违例，再求重叠多边形。

候选流程为：选切割矩形 -> 计算横纵长度 -> 分轮采样 -> 去重 -> 打分 -> 排序与限额。
`getPatchSampleCoordList` 共用首轮端点、后续中点采样规则，横纵矩形公式仍显式保留。
首轮补充端点使用精确切割边界，即使它与枚举网格不对齐也保持原行为。
`updatePatchCost` 统一计算 fixed/routed cost、方向和重叠面积。
Patch 初始化仅查询 minimum-area 违例；shadow 不保存违例惩罚区域，候选 DRC 判优仍检查其他违例是否增加。
每轮只给新增 patch 打分，零代价候选足够后停止细化，避免先完整枚举再丢弃。

| selectPatch 的情况 | 当前行为 |
| --- | --- |
| 无候选 | kNone，不追加 patch |
| 只有一个候选 | kSingleCandidate，直接选择，不调用候选 DRC |
| 多个候选且有改善 | kImproved，选择排序中首个改善候选 |
| 多个候选均未改善 | kBestEffort，保留排序第一的候选 |

判优要求其他环境违例和跨 net 违例按规则类型分别不增加，box 内 minimum-area 数量严格减少。
但原、新两边都没有 box 内 minimum-area 时，不要求凭空产生一次严格减少。
“按类型不增加”不能改成总数不增加，也不要求一次解决全部 minimum-area。

候选检查复用 DETask：只临时 push/pop 当前候选指针，不修改已接受 patch 向量。
已接受向量可能被 DETask 借用，选择过程中扩容会使指针失效。
当前 task 的旧 patch 在 patch DRC 中被工作区内已接受 patch 替代，不能同时检查两份。

## 7. 空间索引与 DRC 视图

| 数据结构 | 存储内容 | 用途与限制 |
| --- | --- | --- |
| PAModel.AccessPointRTree | 候选 AP 坐标和指针 | 邻近 box 获取候选；候选存储需保持稳定 |
| PAFixedGeometry | 原始、未膨胀矩形及来源顺序，按层 RTree 索引 | DRC 输入与原始几何重叠查询；对象仍归 DataManager 所有 |
| PAShadow | 按规则膨胀的代价几何 | Patch 代价查询；不能作为原始 DRC 几何 |
| PANode graph | 轨道节点、邻接、方向占用与代价 | 搜索及重跑；不是矩形几何数据库 |

PAFixedGeometry 的多窗口查询要先按来源下标排序、去重，不能暴露 RTree 遍历顺序。
其 net 列表还用于保留“当前窗口内没有 shape 的 checked net”。
PAShadow 的 fixed index 一次批量构建；routed index 保存贡献计数以支持平衡增删；
同 net 免罚和重合但不同来源的几何语义不能混淆。

Route DRC 有完整 result/patch 与 AP-via-only 两种视图。
两者共享固定几何，但 AP-via-only 不含其他结果与 patch，并跳过 single-net violation。
Box、dirty、full 三种入口对 checked net 的范围不同，不能用一个无差别全量合并器代替。
DETask 内存在指针借用，因此必须在调用完成前保持底层对象及向量地址有效。

## 8. 违例、Dirty DRC 与最优结果

违例按其矩形中点归属于唯一 box；边界违例不应因为当前 box 没有可布 task 而丢失。
需要 route 的 box，或拥有已有违例的 box，都标记 dirty。
本轮所有 stage 完成后，用 dirty box 的完整 real_rect 扩大 detection_distance，
得到需要重查的 box 集合。

- Dirty 比例小于 25%：buildPAEnvironment(..., true) 收集包括 active owner 的当前结果，
  在每个 dirty box 的各 routing layer 原始 box 区域检查，只保留属于该 box 的违例。
- Dirty 比例达到 25%：直接检查当前完整 owner 几何，避免大量重复局部检查。
- 两种模式均保留普通 route 与 AP via 检查，并对归并结果去重。

Box 和 model 的最优结果按 getViolationScore 比较；相同分数允许后来的结果替换。
空违例列表可以是最优有效结果，必须用 valid 标记而不是 empty 判断是否已有快照。
AP、线段、patch 与对应违例要一起恢复，不能只回退线段。

## 9. 修改与验证

只修改 PA 时优先保持 PinAccessor.cpp 内现有阶段边界，不新建通用框架或额外实现文件。
改变输入范围、排序、采样、代价、停止条件或 ownership 都可能改变输出，不能只检查能否编译。

| 改动范围 | 首选回归 |
| --- | --- |
| AP、target、裁剪、patch 采样 | test_pa_candidates |
| route 工作区、队列、shadow | test_pa_state，加 test_pa_candidates 的完整路由签名 |
| DRC 输入、task 所有权、重跑、patch 选择 | test_pa_drc |
| 任务流程、并行边界、发布或跨迭代行为 | 上述三项及指定完整设计对比 |

## 10. 维护检查清单

1. 新状态是否有明确读取方、唯一所有者和清理时机？能否由现有数据直接表达？
2. task_idx 是否仍稳定？是否只重排 task_order_list？
3. 新查询使用原始几何还是膨胀代价几何？net/layer、开闭重叠边界是否相同？
4. 同一结果是否经 owner、env、live task 多条路径重复计入？
5. 修改容器时是否仍有人借用元素指针？是否跨越 stage barrier？
6. 拆函数是否真正揭示策略或复用相同语义，而不只是搬走嵌套代码？
